Handwritten Math, from Recognition to Grading

A graph-based online HMER pipeline — what actually moved its accuracy, and why the same system is far more useful as a grader than as a recognizer.

This project reads handwritten mathematics from pen strokes. It is built as four replaceable stages rather than one end-to-end transformer, which makes each stage measurable in isolation — and, as it turns out, makes the failure modes legible.

pen strokes
  → [1] which strokes form one symbol   (53K-parameter ranker)
  → [2] which symbol is it              (1D-CNN over stroke sequences)
  → [3] how do symbols relate           (GNN + arborescence decoding)
  → [4] LaTeX

Stage 1 is the subject of a short paper at DAS 2026: a 53K-parameter proposal stage that keeps 99.93% of correct symbol candidates while cutting the candidate set by roughly 29× against exhaustive enumeration.

The gap between stages and the whole

Individual stages look strong. The structure GNN reaches 0.877 exact-match given gold segmentation; per-symbol accuracy sits above 93%. But errors compound over roughly 19 tokens per expression, and whole-expression accuracy is what a user experiences. Measured end-to-end on a held-out set, the system landed near 37%.

The interesting question was not "how do we make it bigger" but "where does the accuracy actually leak, and what is the cheapest thing that recovers it."

What moved the number

The diagnosis: the pipeline's generation was good and its selection was bad. Stage 1 keeps the right segmentation 99.93% of the time but picks it only ~61% of the time. The symbol classifier's top-3 accuracy exceeds its top-1 by roughly three points. The correct answer was usually present and losing the ranking.

So the work went into selection, not recognition. Each row below is measured against the same held-out development split, with hyperparameters tuned by two-fold cross-validation:

The language model was trained on 780,086 expressions assembled from public handwriting corpora, with every expression appearing in the evaluation splits removed first — 4,769 of them. Without that filter the model memorizes what it is being tested on and the entire improvement is an artifact.

Three findings worth more than the number

A one-line string count captured most of what the language model appeared to contribute. The LM looked worth +6.75 points. Inspecting which expressions it fixed showed the dominant edit was deleting the letters of an INVALID placeholder — something a substring count does for free. Controlling for that, the language model's genuine contribution was +3.0 points, and those fixes were the context-dependent confusions it was supposed to fix: − versus =, l g versus \log.

A 6-gram Kneser-Ney model beat a small Transformer. Held-out perplexity 6.32 in 37 seconds of training, against 7.23 in 530 seconds for a 5.3M-parameter Transformer on identical data. The cheap incumbent won, as it usually does.

A symbol model's confusion table does not predict where end-to-end errors come from. The isolated symbol classifier's top confusions are 1↔|, x↔X↔×, 2↔z. None of them appear among the errors that reranking actually fixed — those were measured on gold segmentation, and the errors that survive to the final output are dominated by segmentation failures instead.

Two approaches that seemed promising did not work, and are recorded as such: widening hypothesis generation threefold moved the ceiling by 1.2 points and the final answer by −0.4; using the language model to prune candidates before the expensive structure prediction lowered the ceiling by 3.2 points.

Why grading, not recognition

48% whole-expression accuracy is not a product. But that number answers a question nobody actually asks. Free-form recognition demands the system produce exactly the right expression out of an unbounded space. Grading does not: the set of plausible answers to a given problem is small and known in advance.

That distinction is worth measuring rather than asserting. Across the evaluation set, the distance from the best of 32 hypotheses to the true answer:

Expressions average 18.6 tokens. Being two tokens off is a failure when the system must produce the answer unaided; it is close enough to identify the answer when only a handful of answers are possible.

Simulating that setting — the correct answer plus two plausible wrong answers, each differing by one or two tokens, as real student mistakes do — the system can grade 72.5% of submissions automatically at 98.3% accuracy and route the rest to a human. Same model, same pipeline; the only difference is knowing what the answers could be.

An earlier version of this simulation reported 98%. It was wrong: the distractors were drawn from other expressions and sat a median of 7 tokens away, which makes the task free. Realistic distractors are one or two tokens from the answer.

Refusal as a feature

Marking a wrong answer correct is the expensive failure — it is the one that reaches a parent. The cost is asymmetric, so the system declines when it is not confident: when the nearest expected answer is still far, or when two expected answers are equally plausible. Those submissions go to a review queue with the student's original ink, not the model's guess. The student sees "your teacher is checking this," never a wrong verdict.

Where this actually stands

Every number above comes from public handwriting corpora written largely by Western adults. The intended users are Korean secondary-school students. Whether any of this transfers is unmeasured, and it is the single largest uncertainty in the project — larger than any remaining modeling question.

Thresholds and combination weights are tuned on a development split; confirmation on the held-out test set is still outstanding. Step-by-step grading of multi-line working is not implemented — currently one problem yields one answer.

A collection tool and a working grading application both exist and run. The next step is not a better model; it is the first few hundred expressions written by the students this is actually for.
